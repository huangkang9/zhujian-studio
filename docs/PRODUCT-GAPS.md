## V0.9 已补入

| 被忽略的实际问题 | 新增功能 | 入口 / 边界 |
| --- | --- | --- |
| 地面和家具完成后，顶面仍是固定白顶 | 逐房间平顶／整体下吊、高度、颜色，计算顶下净高 | 选中房间 → 顶面与踢脚线；漫游显示顶面，外部布置隐藏顶面 |
| 踢脚线没有跟随房间设计 | 每房间启用、高度、厚度、颜色 | 仅房间内侧；门洞断开。无倒角、异形线脚或节点工艺 |
| 夜景只有统一灯光 | 房间基础照明和每盏灯具可独立开关、2200–6500 K、0–300% 强度、自动／日间常亮 | 选中房间或灯具；实时最多 16 个启用点光源，房间基础灯优先；不是 IES／lux 计算 |
| 好看的布置可能挡门或碰顶 | 从关闭到当前开启角度的门扇扫掠检查，闭门按 90° 预检；家具顶端与顶下净高检查 | 图纸检查 → 定位；离散角度和外包轮廓近似，不替代人体工学或工程规范 |
| 缺少装修物料和人工费用 | 房间地面／墙面／顶面／踢脚线与家具清单，主材、辅料、人工分别计价 | 顶部「用量 / 预算」；墙面扣门窗，同一隔墙两面分房间计入 |
| 材料损耗容易遗漏 | 主材损耗、目标预算、预备费、房间筛选、项目计入开关、品牌和备注 | 主材单独增加损耗；辅料和人工按原始工程量。空白单价明确为待报价 |
| 清单未覆盖水电、拆改、防水、运输等 | 自定义项目、单位与工程量，可删除、撤销，CSV 导出 | 自定义项由用户输入数量与价格，不生成未经核对的市场报价 |

## 后续缺口与优先次序

| 优先级 | 能力 | 需要完成的工作 | 当前状态 |
| --- | --- | --- | --- |
| P1 | 净尺寸与结构信息 | 轴线／净尺寸明确切换、墙面偏移、非矩形净面积、结构柱／梁、承重属性及拆改标识 | 已增加人工结构声明、承重编辑保护和墙面吸附测量；仍按轴线面积，无完整拆改状态、梁柱或自动净尺寸图 |
| P1 | 布置效率 | 多选、分组、锁定、隐藏、对齐、等距分布、连续复制、吸附参考线 | 当前主要为单对象编辑；没有这些完整组合工具 |
| P1 | 真实家具模型 | GLB/GLTF 导入、单位和朝向校正、碰撞轮廓、压缩与 LOD、材质映射、授权资产库 | 60 款程序化家具；没有品牌模型资产授权库 |
| P1 | 方案决策 | 可命名的版本快照、相同视角 A/B 对比、变更记录、预算差异 | 有本机项目复制和撤销；没有完整方案对比工作台 |
| P1 | 真正的视觉验收 | 目标桌面／移动浏览器 WebGL 检查、触屏操作、加载时间、交互帧率、屏幕阅读器 | 当前运行环境缺少 Sites 指定浏览器工具，尚未验收 |
| P2 | 深化硬装 | 多级吊顶、灯槽、背景墙、墙地砖精确起铺点／排砖切割、异形饰面及工程量联动 | 目前只有平顶与整体下吊、程序化纹理；没有排砖切割排料 |
| P2 | 橱柜／衣柜定制 | 柜体板件、隔板抽屉、门板开合、五金、台面开孔、板件和工艺清单 | 当前家具是外包尺寸可调模型；不是可拆单定制柜 |
| P2 | 渲染交付 | 可保存视点、高分辨率渲染、360/720 全景、GI／阴影、IES 灯具、渲染队列 | 实时 Three.js、截图、漫游、四时预览；非照片级云渲染 |
| P2 | 水电与机电 | 插座开关、给排水、照明回路、管线、设备避让、图例与剖面表达 | 未实现；自定义预算只记录费用，不代表已经设计管线 |
| P2 | 完整出图 | 多视图图册、立面／剖面、拆改图、水电图、节点详图、统一专业图框编号 | 已有平面 DXF/SVG 和固定比例打印；不是完整施工图集 |
| P3 | 多层与复杂建筑 | 楼层、楼梯、坡屋面、曲墙、洞口跨层、BIM 数据交换 | 单层直墙模型 |
| P3 | 协作与交付管理 | 云端工程存储、跨设备同步、多人权限、评论审阅、客户分享和版本回滚 | 本机 IndexedDB + JSON 备份；网站私有不代表项目数据已云备份 |
| P3 | 供应链与采购 | 厂商品牌／SKU、实时价格、库存、采购、订单、生产拆单对接 | 手动报价清单；没有供应链 API 或真实商品购买入口 |

## 数据与品质边界

- AI：真实 API 转发已接入，但需要用户配置有效 Key；固定草图测试不是实时服务商调用。未标注尺寸仍需要人工复核。
- 几何：房间身份由墙节点构成。改变拓扑（拆分／合并房间）可能生成新的房间 ID，旧房间材质／预算不会自动推断迁移，需重新核对。
- 预算：按房间轴线边界估算，主材单价人工填写；墙厚、转角接缝、工艺、安装、税费和现场损耗可能导致差异。更换家具款式或材质后需重新核价。
- 验证：自动测试覆盖数值、模型、保存和非 WebGL DOM；没有替代真实浏览器视觉、触屏、照度或施工验收。
